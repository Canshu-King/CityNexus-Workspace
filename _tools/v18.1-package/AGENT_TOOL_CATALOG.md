# Agent Tool Catalog

The runtime catalog is generated by `backend/app/agent/tool_catalog.py` and
is also served by `GET /api/v1/agent/tools`.

1. `inspect_journey`
2. `inspect_twin`
3. `list_replans`
4. `search_city_services`
5. `request_replan`
6. `accept_replan`

The MCP adapter exposes the coherent eleven-tool V2 surface from one server;
the pinned V1 surface remains six tools. Payment capture, refund, C4 mutation,
policy mutation, arbitrary HTTP/SQL, terminal, file, and browser tools are not
registered.

The six-tool V1 surface is intentionally pinned for compatibility, not a
permanent read-only Agent design. Typed V2 commands resolve the same server
principal, ownership/state facts, provider status, loss, and Autonomy Envelope
before execution; a high-risk request remains visible to the Agent and returns
`REQUIRE_CONFIRMATION` or `REQUIRE_STEP_UP` instead of being hidden from it.

The V1 catalog remains pinned at six tools. The expanded V2 catalog is served
by `/api/v1/agent/tools/v2` and the separate `build_mcp_v2_server()` adapter,
with the following typed commands:

- `replace_activity`
- `reschedule_activity`
- `create_booking`
- `cancel_refundable_booking`
- `request_commitment_change`

`replace_activity` accepts either another active-plan Activity or a
server-owned `replacement_place_id` returned by `search_city_services`; the
latter materializes a new candidate without cannibalizing a scheduled Activity.

Every V2 mutation uses server-issued, journey-scoped approval receipts when
the Delegation Policy does not allow automatic execution. The caller-owned
`user_confirmed` boolean is retained only for client compatibility and is
never an authority signal.
